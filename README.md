# 消失点 / Vanishing Point

一个用 Qt 6 写的**透视绘画工具**：在一张照片上标定若干透视平面，之后画笔、图章、选区和贴入的图像都会自动贴合这些平面的透视关系——笔触随距离缩短，贴入的海报跟着墙面一起倾斜，跨过两个相邻平面时内容还能连续地越过接缝。

## 功能特性

- **透视平面**：依次点击四个角点建立平面；拖动控制点/边缘调整；Ctrl 从边缘拖出与之垂直的新平面（共用边自动锁定）。
- **透视画笔**：在平面内拖动绘制，笔触按平面单应产生透视缩短，并可越过平面边界向外延伸。可调直径、硬度、不透明度、颜色。
- **仿制图章**：Alt+左键取样，左键拖动仿制；支持「对齐」（源点持续跟随光标）与非对齐两种模式。
- **选框工具**：沿透视建立矩形选区，可整体移动；Alt 拖动把选区内容复制成浮动图像；**Ctrl 拖动把鼠标处的区域克隆进选区，松手后生成为可继续移动的浮动图像**。
- **浮动图像**：粘贴（Ctrl+V）、拖入图片文件、或从选区生成；可吸附到任意平面、沿曲面移动、缩放、旋转，跨平面时自动分段投影。
- **历史记录**：撤销/重做 40 步。结构（平面、浮动图像）整份快照，绘画层只记录脏矩形增量。

## 构建

需要 Qt 6.5 及以上（Core / Gui / Widgets）、CMake 3.19 及以上、支持 C++17 的编译器。Windows 下用 Qt 6.11.2 + MinGW 13.1 验证过，MSVC 亦可。

```bash
cmake -S . -B build -G Ninja -DCMAKE_PREFIX_PATH=<Qt 安装前缀>
cmake --build build
```

- 用 Qt Creator 直接打开 `CMakeLists.txt` 同样可以，仓库里已保留 `build/Desktop_Qt_*_MinGW_64_bit_Debug` 与 `..._Release` 两套构建目录。
- 命令行构建时请把 Qt 与编译器的 `bin` 目录放进 `PATH`（Windows 下需要 Qt 运行库才能启动程序）。
- 单元测试在 `tests/` 下，随主项目一起构建（无需额外开关）；构建后在构建目录跑 `ctest --output-on-failure` 即可。

## 操作说明

打开一张图片后自动进入创建平面工具，之后用左侧按钮或快捷键切换工具。

| 工具 | 快捷键 | 用法 |
| --- | --- | --- |
| 创建平面 | `C` | 依次点击四个角点，第四点落下即生成平面；落点前实时预览下一条边，点了第 3 个后同时预览收口的两条边 |
| 编辑平面 | `V` | 拖动内部沿原无限透视平面移动；拖动控制点/边缘调整；Ctrl 从边缘拖出垂直平面；Ctrl+单击在被遮挡的平面之间循环选择 |
| 画笔工具 | `B` | 在平面内拖动绘制，笔触可延伸到平面之外 |
| 图章工具 | `S` | Alt+左键设置源点，左键拖动仿制 |
| 变换工具 | `T` | 拖动控制点缩放，角点外侧拖动旋转；Shift 等比/15°；Alt 中心缩放；Esc 取消 |
| 选框工具 | `M` | 拖动创建透视选区；Shift 正方形；Alt 拖动复制内容为浮动图像；Ctrl 拖动克隆为浮动图像 |

其他操作：

| 操作 | 快捷键 |
| --- | --- |
| 打开图像 / 导出结果 | `Ctrl+O` / `Ctrl+S`，或工具栏按钮（PNG、JPG） |
| 粘贴为浮动图像 | `Ctrl+V` |
| 点击别处（有图像选中时） | 把浮动图像合并进绘画层，之后不能再单独操作 |
| 撤销 / 重做 | `Ctrl+Z` / `Ctrl+Shift+Z` |
| 删除选中的图像或平面 | `Delete` / `Backspace` |
| 取消当前操作 | `Esc` |
| 拖入图片文件 | 未打开文档时作为背景，已打开时成为浮动图像 |

浮动图像选中时可以自由移动、缩放、旋转；一旦点击别处，它就按当前几何合并进绘画层并从图像列表移除，
内容与绘画层彻底合为一体（撤销可整体回退这一步）。

## 核心设计：内容与平面解耦

这是整个项目最重要的一条约定，也是平面能被自由增删改而不破坏已有内容的原因：

- **平面只提供透视规则（几何），不持有任何内容。**
- **画笔笔触**烘焙在与画布同尺寸的「绘画层」上，按绘制瞬间锁定的面片单应落到画布坐标系，与平面之后如何修改无关。
- **浮动图像**各自携带吸附瞬间的几何快照（面片 + 展开曲面坐标）。此后删除或修改平面，已经存在的内容不会跟着变形。
- **展开曲面（surface group）**：相邻的平面（例如从一条边拖出的垂直平面）共享一套展开后的 2D 曲面坐标，因此同一张浮动图像可以跨越接缝，而每个面仍用各自的单应变换投影回画布。

## 代码结构

```
VanishingCore（只依赖 Qt Core/Gui，纯逻辑，便于测试）
├── planemath.*            平面几何、透视构造、命中测试
├── projectivemapping.*    单应变换（含无穷远点、地平线处理）
├── canvasdocument.*       文档模型：背景 / 平面 / 绘画层 / 浮动图像 + 历史
├── floatingimagemath.*    浮动图像在画布与展开曲面之间的坐标换算
├── imagegeometry.*        浮动图像的投影补丁、轮廓、控制点、命中测试（带缓存）
├── paintengine.*          透视笔刷（UV 空间软边笔触 → 绘画层）
├── clonestampengine.*     仿制图章的取样与对齐
├── clonetool.*            图章工具的拖动状态
├── imagetransformtool.*   变换工具的缩放 / 旋转状态机
├── planeedittool.*        平面编辑与垂直平面拖出的状态机
├── scenerenderer.*        场景渲染（背景 + 绘画层 + 浮动图像 + 辅助线）
└── scenecontentcache.*    视口静态内容缓存，避免每帧重绘整个场景

VanishingWidgets（依赖 Qt Widgets 的界面层）
├── perspectivecanvas.*    画布控件：视图变换、输入路由、交互事务协调
└── mainwindow.*           主窗口：工具栏、参数面板、信号接线
```

分层的关键约束：`VanishingCore` 不引入任何 Widgets 头；几何、文档、绘画引擎、渲染各自独立，工具只维护自己的拖动状态，由 `PerspectiveCanvas` 负责分派与提交事务。

想改代码的话，[docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) 里有更深入的导览：分层理由、三套坐标系统的区别、一次操作的数据流、各模块职责速查与常见陷阱。

## 历史与性能

- 结构状态（平面 + 浮动图像）体积小、位图依赖隐式共享，直接整份快照入栈。
- 绘画层若整份入栈，几十步历史就会失控，因此只记录本次操作脏矩形的前后像素。
- 交互事务 `beginEdit / commitEdit / cancelEdit` 只保留操作前的一份 COW 快照，Esc 取消或拖动失败时可完整回退。
- 视口静态内容按「文档内容 + 视图参数」生成 key 缓存，蚂蚁线、控制点与网格由画布实时叠加绘制。
- 区域克隆、选区提取等逐像素运算改成按单应补丁一次性栅格化，避免逐像素反算。

## 已知边界

- 平面被删除后，原本吸附其上的浮动图像不会消失（内容持有自己的几何快照），但会继续按旧快照显示。
- 绘画层是与画布同尺寸的单一光栅层，笔触一旦落下就与平面解耦，无法再按平面单独移动。
